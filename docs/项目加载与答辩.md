## 0. 先背两段自述

**30 秒版**

> 这个实验用两块 STM32F407，通过 CAN 总线互联。任意一块板按 KEY0，两块板同时采集本板的
> 温度、湿度、光敏、eCO₂、TVOC，各自显示在 LCD 上，板 1 的数据通过 CAN 实时送到板 2 显示；
> 两块板各自用 WiFi 把数据上传到 PC 的 MySQL，网页分两页展示。
> 然后用采集到的数据训练一个小神经网络，用 X-CUBE-AI 转成 C 代码跑在 STM32 上，
> 判断一条数据来自哪块板。

**2 分钟版**（在上面基础上补 4 个数字）

> 采样 1 Hz，CAN 500 kbps；模型是 2→16→16→2 的 MLP，354 个参数、1.4 KB 权重；
> 训练/验证准确率 1.0000，留出的 10 条全部判对；
> 数据按演示摆放采集，避免"采集时一个环境、演示时另一个环境"。

## 2. 老师可能问的问题

### A. 方案与需求（6 题）

**A1. 题目说「CAN 或 485」，为什么选 CAN？**
CAN 是差分总线，自带 CRC、ACK、仲裁和错误帧，两节点 500 kbps 下几乎不用自己写可靠性逻辑；
板载就有 TJA1050 收发器，实验六也跑通过。485 只是电气层，帧格式、冲突、重传都要自己造。

**A2. 两块板为什么要「等价」？**
题目说「板1 按键1 开始」，但没要求只能板1 控制。做成等价后，任意一块的 KEY0/KEY1 都通过
CAN 控制帧（板1 发 `0x200`、板2 发 `0x201`）通知对板，演示时不用特意找板1。
实现上只有一个入口 `App_SetRunning(run, send_ctrl)`，收到对板控制帧时 `send_ctrl=0`，**绝不转发**，避免两块板互相刷帧。

**A3. 为什么上电两块板都不采集？**
实验六是「从机上电即采」，那样「两块同时开始」就无从谈起。实验七改成上电都不采、按键才采，
这是需求确认时明确的一条（A5）。

**A4. 两块板代码是一样的吗？**
一份 `app_node.c`，靠 `BOARD_SEL` / `IS_MASTER` 在编译期分叉；Keil 里两个 Target
（board1/board2）共用同一套源码，只是宏不同。

**A5. 题目写 OLED，你为什么用 LCD？**
用的是 2.8″ ILI9341（240×320），需求确认时定的：实验六已有成熟 FSMC 驱动和中文点阵，
换 OLED 要重做字库和布局，收益只是「名字对得上」。功能上完全覆盖题目要求。

**A6. 为什么采样是 1 秒一次？**
ESP-01S 实测 CIPSEND 上限约 1.5 次/秒，两块板各 1 帧/秒总负载更低；传感器（SHT30/SGP30）
也不需要更快的刷新。网页和曲线都是按 1 Hz 设计的。

### B. 硬件与 CAN（7 题）

**B1. CAN 帧怎么定义的？**
标准帧、500 kbps、DLC≤8：
`0x100`（板1→板2：seq/temp/humi/light）、`0x101`（eco2/tvoc/status/board）、
`0x110/0x111`（板2→板1，同结构，用于交叉验证）、`0x200/0x201`（控制帧）、`0x180`（心跳，1 Hz）。

**B2. 5 个传感器值超过 8 字节怎么办？**
拆两帧。`0x100` 放序号+温湿光，`0x101` 放 CO₂/TVOC/状态/板号；温度湿度按 ×10 存成有符号整数。

**B3. 为什么用轮询不用 CAN 中断？**
数据率只有 1 Hz，`CanTask` 10 ms 轮询 FIFO0 足够；减少中断嵌套和优先级问题。
CAN 初始化也故意不调 `HAL_CAN_Start()`——它内部等 INAK 依赖 `HAL_GetTick()`，
而本工程 HAL 时基在 TIM6，会死循环（实验六板2 白屏的根因），现在直接清 INRQ 进 Normal。

**B4. 板2 怎么知道板1 掉线？**
3 秒收不到任何 `0x1xx` 判离线，「板1 区」显示 `--`；板1 侧靠 `0x180` 心跳判断板2。

**B5. 呼吸灯怎么做的？**
TIM7 软 PWM，20 ms 步进改变占空比，三色 LED 同步呼吸。两板共用 `led_effect.c`，
只有 `running=1` 才亮；上电不亮。

**B6. 为什么不用外接 120 Ω？**
每块板自带 R35（120 Ω），两块板并联约 60 Ω，短双绞线正合适；再外接会变成 40 Ω，反而加重负载。

**B7. 如果真的没有波形，先查什么？**
P21 跳线（PA11/PA12 与 USB 座二选一）→ 两板共地 → 波特率都是 500 kbps → 串口敲 `c` 发心跳。

### C. WiFi / 协议 / 上位机（7 题）

**C1. 两块板都是 client，谁连谁？**
两块板都是 STA，连 PC 的移动热点（2.4 GHz），各自 TCP 连 `PC:8080`；
板间数据走 CAN，WiFi 只负责上报，两条链路互不耦合。

**C2. 协议长什么样？**
文本帧、逗号分隔：
`H,<姓名>,<学号>,<board>`（握手，板号在最后）、
`D,<board>,<up_ms>,<seq>,<t>,<h>,<light>,<eco2>,<tvoc>,<OK|ALM>,<ai_cls>,<ai_conf>`（1 Hz）、
`S,<board>,START|STOP`（采集状态变化时发）。

**C3. 网页怎么知道采集开始/停止？**
板端 `running` 变化时发 `S` 帧，**发送成功才更新状态**；链路重连后补发一次当前状态，
所以网页打开就能看到正确状态。10 秒收不到任何帧显示「离线」。

**C4. 两块板的采集时间怎么对齐？**
每帧带本板上电毫秒 `up_ms`；PC 为每块板单独标定 offset，换算成 `sample_time`，
同时另存 `recv_time`，可以看链路延迟。

**C5. WiFi 断了怎么办？**
三条通路：① 模块吐 `0,CLOSED` → 标记并重发 `AT+CIPSTART`；② `CIPSEND` 失败兜底（半开连接）；
③ 周期补连（开机时 PC 没开热点也能自己连上）。重连成功必须复位 `+IPD` 解析状态机，否则吃帧。

**C6. 网页为什么是两页？**
题目明确要求「分 2 页」：页①列表（分页/筛选/编辑/导出 CSV/AI 判定列），页②图形（5 种风格）。

**C7. 上位机用了什么框架？**
单文件 Python，标准库 `socket` + `http.server`，零第三方依赖（除可选的 pymysql）；
HTML/JS 内嵌，Canvas 画 5 种图。换机器只要 Python 就能跑。

### D. 神经网络（10 题，重点）

**D1. 模型结构是什么？**
MLP：输入 2 维（温度、湿度）→ 16 → 16 → 2（softmax）。
参数量 354（1.38 KB float32），MACC 416，activations 128 B。

**D2. 为什么输入只有 2 维？题目不是 5 个传感器吗？**
采集、显示、上报仍然是 5 项，**只是网络的输入选了最稳的 2 个**。原因是实测：
- 光敏：同一块板自己就能从 1200 漂到 1519（+27%，开灯/挡光），跨板差异里混着环境光；
- CO₂：跨板只有 0.20σ，TVOC 0.86σ，几乎没有区分度；
- 温湿度是**器件个体差异**，当前这批数据里湿度 10.62σ、温度 5.60σ，单通道 AUC 都是 1.000。
所以 `--features` 默认 `temp,humi`；要 5 通道重训也可以：`--features temp,humi,light,eco2,tvoc`。

**D3. 那题目问「是哪个传感器采集的数据」，怎么回答？**
一条记录本来就是 5 个传感器**同一时刻一起采**的，不存在「这条是温度采的、那条是光敏采的」
这种互斥标签。所以拆成两问：① 判**哪块板**（2 分类）；② 输出**主导通道**
（单通道可分性 + AUC）。这是需求确认时定下的口径，报告里有完整表格。

**D4. 准确率 100% 是不是过拟合？**
有三层证据：
① 每板最后 5 条（共 10 条）**完全不参与训练**，留出测试 10/10；
② 换一个采集批次 210 条做跨批次测试，100%；
③ 烧进板子实测 201 条，判对 200 条（99.5%，唯一错的是开机第一条 SGP30 还在预热）。
（②③ 是上一版 5 通道模型的实测；现在这版 2 通道**答辩前要按同样口径重测一遍**，别拿旧数字硬说。）
而且数据本身单通道就有 5~10σ（AUC 1.000），连逻辑回归都 100%——是数据可分，不是模型背答案。

**D5. 归一化为什么要在板子上再做一遍？**
训练时用 z-score（mean/std 由训练集算），板上没有 sklearn，所以 `train_nn.py` 把
mean/std 导出成 `ai_norm.h`，`Ai_Infer()` 里做同一套变换再喂 `ai_run()`。
这是「PC 训练 + 板上推理」最容易错的一环，参数不一致会得到完全离谱的判定。

**D6. 模型怎么进的 Keil 工程？**
Keras 训练 → 导出 `model.onnx` → `stedgeai generate` 生成 7 个 `network*.c/h` →
放进 `firmware/USER/AI/` → `make_project.py` 挂进两个 Target → 编译 0E0W。
`ai_model.c` 是一层薄封装：归一化 + 调 `ai_run()` + 取 softmax 两类的较大者。

**D7. 为什么用 ONNX 不用 .h5？**
Keras 3 的 `.h5`，stedgeai 10.2.1 认不了；`.onnx` 实测和 Keras 数值等价，是唯一稳定可用的格式。

**D8. 为什么不做 int8 量化？**
模型只有 354 个参数、1.38 KB，F407 有单精度 FPU，float32 完全没压力；
量化收益（省几百字节）远小于输入量化误差带来的风险。

**D9. 10 条演示样本怎么选的？**
每块板 CSV 里**最后 5 条**（时间上最新），不参与训练，固化进 `ai_test10.h`；
串口 `n` 逐条推理。这样演示的是「后续采集、模型没见过」的数据。

**D10. CAN 交叉验证是什么？**
板2 把自己的原始 5 项经 `0x110/0x111` 回传板1；板1 用**自己板上同一份模型**判，
屏上 `OWN b1 99%` / `PEER b2 98%`。证明模型判的是数据来源，不是「谁在推理」。

### E. 数据与实验方法（5 题）

**E1. 为什么强调「采集摆放 = 演示摆放」？**
早期 852 条是两板摆得较开时采的，模型会依赖光敏/CO₂ 的环境差；演示时两板只隔 10 cm，
这个差会消失（CO₂ 两板差从 459 ppm 降到 99 ppm），模型当场翻车。
所以最终数据必须按演示摆法重采。

**E2. 训练前为什么要做可分性检验？**
如果两板数据根本分不开，训出来就是随机模型。`check_separability.py` 用 5 折交叉验证 +
逐通道 AUC + PCA，准确率 <80% 就不让往下走，先调摆放再重采。

**E3. 数据量够吗？**
题面要求每板 ≥100 条。当前 `lab7.csv` 是 147 条（板1 59 / 板2 88），**板1 还差 41 条**，
答辩前要补采；旧的 207 条（106/101）是 5 通道那版的数据。

**E4. ALM 行为什么要剔除？**
ALM 是板1 超温报警（默认 35 ℃）。如果阈值设 28 ℃，室温就会触发，导出时默认 `status='OK'`
会把大片数据剔掉（真踩过：采 161 条剩 42 条）。所以阈值默认改 35 ℃，且只有板1 判 ALM。

**E5. SGP30 第一条为什么是 400 / 0？**
上电预热期读数固定为 400 ppm / 0~2 ppb，属于无效数据。导出时只留 OK 行、演示前先跑 15 秒，
就是为了避开它。

### F. 工程与踩坑（5 题）

**F1. 为什么不用 CubeMX 的 GENERATE CODE？**
① 中文路径下 stedgeai 直接崩（`'gbk' codec can't encode`）；
② 它会改工程：第一个 Target 改名、给文件加「文件级 IncludePath」（AC5 报 C4065E）、
删 `system_stm32f4xx.c`、把 startup 的 `Stack_Size` 改回 0x800。
所以用命令行 `gen_ai_code.py`，只覆盖 7 个网络文件，不碰工程结构。

**F2. 怎么保证板上跑的是最新模型？**
训练不可复现（同 seed 两次权重都不同），所以每次必须
**训练 → 转 C → 编译 → 烧写**一条链走完。`check_sync.py --hex` 比对
`model.onnx` 与 `network_data_params.c` 的时间戳，并打印两个 hex 的 MD5。

**F3. 为什么有两个 Target？**
两板硬件相同、功能等价，只差 `BOARD_SEL`（板1 广播、板2 回传）。一个工程两个 Target
比两套代码好维护，也不会出现「改了板1 忘了板2」。

**F4. 编译资源占用多少？**
board1：Code 45,740 B + RO 16,904 B + RW 2,372 B ≈ **63.5 KB Flash**；
RW + ZI = 32,840 B ≈ **32 KB RAM**。F407ZGT6 是 1 MB Flash / 192 KB RAM，余量很大。

**F5. 如果工程被 CubeMX 重新生成坏了怎么办？**
跑 `python tools\make_project.py firmware` 恢复 USER 文件组和两个 Target；
再确认 startup 的 `Stack_Size` 还是 0x1000。

### G. 追问 / 挖坑（6 题）

**G1. 如果我把两块板交换位置，还能判对吗？**
不能保证。模型学的是**这两块板**的温湿度个体差异，交换后标签就反了。
这正好说明它学的是「器件身份」，不是「位置」。

**G2. 如果换两套新的传感器模块？**
需要重新采集、重训。器件个体差异换了，旧模型不再适用——这是这类「判来源」任务的固有前提。

**G3. 加第三块板要改什么？**
输出层改 3 类（softmax），CAN 增加板3 的 ID，PC 端协议不用大改（board 字段已经是通用的）。
当前工程按题目收敛成两板。

**G4. 为什么不在 PC 上推理，非要在板子上跑？**
题目要求「在串口判定」+ X-CUBE-AI 路线；板上推理断网也能用、延迟低、不依赖 PC。
PC 只负责收数据和展示。

**G5. 模型能不能判断「这是温度还是湿度传感器采的」？**
不能，也不应该——5 个传感器是同时采样的，一条记录同时属于 5 个通道。
能回答的是「哪个通道对判板贡献最大」，见 D3。

**G6. 如果现场重训，你要多久？**
训练本身约 20~30 秒（150 epoch），转 C + 编译约 3~4 分钟，总共 5 分钟内。
用 `一键重训.bat` 一条命令；但本机缺 stedgeai，现场转 C 前要先补装 X-CUBE-AI Utilities。

## 3. 现场翻车怎么应对

| 现象 | 一句话解释 + 动作 |
|---|---|
| CAN 一条波形都没有 | 「P21 跳线是 USB/CAN 二选一」→ 插上 3–5、4–6 再试 |
| 板2「板1 区」不刷新 | 先看板1 是否在采（KEY0），再查双绞线 A/B、共地 |
| 网页连上但没数据 | 串口 `w` 看 WiFi 状态机；检查热点名/密码、2.4 GHz、防火墙 8080 |
| 网页打不开 | 8000 端口被旧进程占了：`Get-NetTCPConnection -LocalPort 8000` 找 PID 杀掉 |
| 板上判定明显不对 | 先 `check_sync.py --hex`；大概率是烧了旧 hex 或没转 C |
| CO₂/TVOC 显示 `---` | SGP30 暖机中，等 15 秒；还不行就 `g` 查 I2C |
| 被问「数据不是只有 147 条吗」 | 承认当前 59/88，说明正在补采；旧的 207 条和上板 201 条可作已完成证据 |
| 被问「文档怎么写的 5 通道」 | 说明今早把特征收敛到温湿度（光敏漂移），文档正在同步；指标以 `ai/report/train_report.md` 为准 |
