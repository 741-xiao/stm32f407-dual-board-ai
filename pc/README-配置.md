# 实验七 · PC 上位机 配置与使用说明

> 给"要用这套东西的人"。板子那边烧好 `board1` / `board2` 两个 hex 就行。

## 一、这套东西做什么

PC 同时接收**两块板**发来的数据（板1、板2 各一条 TCP 连接，端口 **8080**），
在控制台打表，网页分 **2 页**：

| 页面 | 地址 | 内容 |
|---|---|---|
| ① 记录列表 | <http://127.0.0.1:8000/> | 采集状态条 + **分页**动态列表（可筛选/排序/编辑/删除/导出 CSV） |
| ② 图形 | <http://127.0.0.1:8000/chart> | **5 种互不重复的风格**：折线 / 柱状 / 面积 / 饼 / 散点 |

两页顶部可互相切换。可选把每条数据写进 MySQL 的 `stm32_lab.lab7_data`
（含题2 的 AI 判定列 `ai_cls` / `ai_conf`）。

- 板号**靠帧里的 `board` 字段识别**（协议 v7），不依赖谁先连、也不依赖 IP。
- 时间标定**按板分别做**：每板各自标定 offset（取"最小偏移"），换算"采集时间"。
  ★ 收到 H 帧（= 该板刚连上/重启）会**重置该板的标定** —— 板子重启后 `up_ms` 从 0 重算，
  不重置的话采集时间会套用旧偏移直接回跳。
- **在线判据**：该板 10s 内**任何帧**都没到 → 判"未连接"（不能用"S 帧多久没来"，
  S 帧是事件驱动的，板2 上电即采只在握手后发一次）。

| 帧 | 格式（协议 v7） |
|---|---|
| 握手 | `H,<姓名>,<学号>,<board>`　★ 板号在**最后一个**字段 |
| 数据 | `D,<board>,<up_ms>,<seq>,<温度>,<湿度>,<光>,<CO2>,<TVOC>,<OK\|ALM>[,<ai_cls>,<ai_conf>]` |
| 状态 | `S,<board>,START\|STOP` —— 采集启停（题1：网页显示"采集开始/停止"） |

> AI 两个字段**可缺省**（阶段5 之前固件不发，上位机自动按需解析）。
> 实验七**没有** C 控制帧 —— 板间控制走 CAN（不占 WiFi）。

## 二、前置条件

1. **电脑开移动热点**（网关固定 `192.168.137.1`；两块板都连它）。
2. **放行防火墙**：TCP **8080**（收数据）和 **8000**（网页）。
3. Python 3（标准库即可跑；**要入库**才需要 `pip install pymysql` + MySQL）。
4. MySQL（可选）：本机 `127.0.0.1:3306`。

## 三、文件

| 文件 | 说明 |
|---|---|
| `upper_computer.py` | **主程序**（单文件、零依赖） |
| `init_db.sql` | 建库建表（幂等，建 `stm32_lab.lab7_data`；**不动 th_data / lab5_data / lab6_data**） |
| `db_local.example.py` | 数据库口令模板 |
| `README-配置.md` | 本文件 |
| 　 | 　 |
| `../tools/pc_sim_boards.py` | **假板模拟器**（没有板子时也能验证 2 页网页/S 帧/AI 列） |

## 四、运行步骤

```bash
# 1) （可选，要入库才做）建库建表 —— 二选一
python tools/init_db.py                            # ★ 推荐：不需要 mysql 命令行
mysql -u root -p < pc/init_db.sql                  # 装了 mysql 客户端的话也行

# 2) （可选，要入库才做）填口令：复制模板 → 改密码
cp pc/db_local.example.py pc/db_local.py     # 然后编辑里面的 DB_PASS

# 3) 跑上位机
python pc/upper_computer.py
```

> ★ `tools/init_db.py` 是幂等的（表已存在不会报错、不会清数据），还能顺手报告
> "库里两板各多少条"，跑完会提示下一步。`--check` 只检查不动结构。

然后两块板上电。**板1 按 KEY1（板上 KEY0）开始采集、按 KEY2（板上 KEY1）停止**
（板2 上电即采）。收不到数据时先看控制台有没有 `[连接] … 识别为 板x`。

- 控制台：`板 / 序号 / up_ms / 温度 / 湿度 / 光敏 / CO2 / TVOC / 状态 / AI板 / AI% / 采集时间`
- 网页① <http://127.0.0.1:8000/>
  - 顶部**采集状态条**：`采集进行中 / 已停止 / 板1 未连接`（由 S 帧驱动，2s 刷新一次）
  - 板号徽标：**板1 蓝 `#378ADD` / 板2 橙 `#EF9F27`**
  - 列表可筛选 / 排序 / 编辑 / 删除 / **分页**（每页 20~500 条可选）/ 导出 CSV
  - **AI 判定**列：板端神经网络的判定结果（`判为板2（96%）✔`）；未推理时显示 `—`
- 网页② <http://127.0.0.1:8000/chart> —— **每种数据一种风格，互不重复**（5 张图）
  | 数据 | 风格 | 看什么 |
  |---|---|---|
  | 温度 ℃ | 折线图 | 两板趋势 |
  | 湿度 %RH | 柱状图 | 两板对比 |
  | 光敏 % | 面积图 | 叠加 |
  | CO₂ ppm | **饼图** | 两板占比 |
  | TVOC ppb | **散点图** | 分布 / 离群 |

## 五、不用板子也能先跑通（假板模拟器）

```bash
python pc/upper_computer.py          # 终端 A：上位机
python tools/pc_sim_boards.py        # 终端 B：假板（127.0.0.1:8080）
#   可选： --ai 带上 AI 判定字段   --secs 60 跑 60 秒   --no-seq 不发 S 帧
```

模拟器会按时间轴自动演示一遍：板2 上电即采 → t=5s "板1 按键1"开始 → t=25s "板1 按键2"停止。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 一直没有 `[连接]` | 热点没开 / 防火墙没放行 8080 / 板子没连上热点（看板子串口） |
| 连上了但**一个字节都没有** | 板端 WiFi 状态机没到 READY（看板子状态页 WiFi 那栏 / 串口敲 `w`） |
| 连上了但没数据 | 板1 还没按 KEY1 开始采集（板2 上电即采，应有数据） |
| 状态条一直"未连接" | 板子掉线，或 10s 内没有任何帧；看控制台有没有 `[断开]` |
| 控制台中文乱码 | 终端编码问题，**不影响数据**（网页和库里都正常） |
| `[DB] 未启用` | 没装 pymysql 或没写 `db_local.py`；不影响接收与显示 |
| 库里没数据 | 表没建（跑 `init_db.sql`）/ 口令错 / 看控制台的 `[DB] 操作出错…` |
| 想清空库重采 | ★ **默认是保留**（实验七的表是题2 的数据集，不能顺手删）。要清空：`STM32_DB_CLEAR=1 python pc/upper_computer.py` |
| 图形页 5 张图空白 | 该板数据点不足（折线/面积/散点需 ≥2 点）；先按 KEY1 采集一会儿 |

## 七、验收对照（题1 · D 组）

- **D1 分 2 页**：`/` 列表页与 `/chart` 图形页可互相导航；
- **D2 动态列表分页**：首/上/下/末页 + 跳页 + 每页条数可选；
- **D3 区分两板与采集时间**：每行有板号徽标（2 色）+ 采集时间（毫秒）；
- **D4 不同风格的图形**：折线 / 柱状 / 面积 / 饼 / 散点，5 种互不重复，按板着色；
- **D5 显示采集开始/停止**：顶部状态条由板端 S 帧驱动（板1 KEY1=开始 / KEY2=停止）；
- **C2/C3 入库**：`lab7_data` 的 `board` / `sample_time` 区分两板与时间，含 `eco2`/`tvoc`/`ai_cls`/`ai_conf`。
