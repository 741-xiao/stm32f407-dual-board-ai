## 一、★★ CAN1：板载收发器 + 板载终端电阻 + **必须短接 P21**

| 项 | 原理图事实 | 对方案的影响 |
|---|---|---|
| 收发器 | **U9 = TJA1050**（板载，VCC5 供电，C36=104 去耦） | 不用外接收发器模块 |
| MCU 侧 | **PA11 → `CAN1_RX` → U9 pin4(R)**；**PA12 → `CAN1_TX` → U9 pin1(D)** | ✅ 与 CubeMX 分配一致，**不需要改** |
| 跳线 | ★★ **P21**（2×3 排针）—— 同一组引脚既接 USB 又接 CAN1，**必须二选一** | **不跳线 = CAN 完全不通** |
| 终端电阻 | **R35 = 120Ω**，**常接**在 CanH–CanL 之间（无跳线可断） | 见下方"终端电阻"一节 |
| 总线引出 | `1_H` / `1_L`（引到"引出接口"） | 只用这两根接总线 |
| CAN2 | U11 = TJA1050 + R49 = 120Ω（本实验不用） | — |

### P21 怎么接（**上板前必做**）

```
        P21
USB_DM1  1 ── 2  USB_DP1        ← 来自 USB 座 J9（经 R63/R64 10Ω）
USB_D-   3 ── 4  USB_D+         ← 就是 MCU 的 PA11 / PA12
CAN1_RX  5 ── 6  CAN1_TX        ← 去 U9 (TJA1050)
```

| 用途 | 短接 |
|---|---|
| **用 CAN1（本实验）** | ★ **3–5 和 4–6**（两个短路帽） |
| 用 USB（不接 CAN） | 1–3 和 2–4 |

> 出厂/上一位使用者可能停在 USB 档 —— **上电前先看 P21 上两个短路帽的位置**。
> 现象对照：**P21 没跳到 CAN 档 = 程序全对、CAN 总线上毫无波形**。

### 终端电阻：**不要再外接 120Ω！**

- 每块板**自带** 120Ω（R35，常接）。
- **三块板并联 ≈ 40Ω**（标准是总线两端各一个、共 60Ω）。
- **短母线（<1m）+ 500kbps 下通常能正常通信**；但 40Ω 略低于 TJA1050 手册的推荐负载（≥45Ω）。
- ⇒ **验收时不要再在总线上加 120Ω**（加了两端会变成 ~30Ω，更差）。
- 若出现"通信时断时续/错误帧多"，**这里就是第一嫌疑**。

## 二、其它核对到的硬件（与方案相关）

| 外设 | 原理图事实 | 影响 |
|---|---|---|
| **I2C1（我们的 SHT30）** | 固件把 I2C1 配在 **PB6/PB7**；但原理图上这两个脚是 **`DCMI_D5` / `DCMI_VSYNC` → 摄像头座 P18** | ★ **板载 I2C 上拉不在我们这条线上**（见下一行）；**必须靠模块自带的上拉** |
| **I2C2（我们的 SGP30）** | CubeMX 已生成，配在 **PF0(SDA) / PF1(SCL)**；原理图上这两个脚**没有接任何板上器件**，只在 **P7 排针**引出 | ✅ 空脚、可直插；同样**无板载上拉**（模块要自带） |
| **板载 I2C 总线** | `IIC_SCL` / `IIC_SDA` 实际在 **PB8 / PB9**，挂着 **AT24C02（U5）** + **4.7K 上拉（R17/R18）**。**没有引出到任何排针** | 我们**用不到**这条；也就拿不到那对 4.7K 上拉 |
| **光敏（我们的 ADC）** | 固件用 **PC0**；原理图上 PC0 = **`I2S_SCK` → 音乐模块 / I2S 座** | 音乐模块**选装** → 不插即空闲；从那个座引 `I2S_SCK` |
| **通用排针引出了哪些脚** | 接口页共引出 48 个脚：PA0/1/2/3/5/7/15、PB0/1/3/4/5/**10/11**、PC4/PC5、PD0/1/5/11-15、PE7-11/14/15、PF0-4/11-15、PG0-5/10 | ★ **PB6/PB7/PB8/PB9/PC0 都不在其中** → 只能从选装座取信号 |
| **可选替代（要动 CubeMX）** | **PB10/PB11 = I2C2_SCL/SDA**，**已引出**（P7 排针 + 串口3蓝牙座）；**PF3/PF4 = ADC3_IN9/IN14** | 嫌从选装座引线别扭时可换（默认不建议） |
| **RS485** | 板载 **U7 = MAX485**，用 **PA2/PA3 = USART2**（485_TX/485_RX/485_RE），360R+120R | 若改用 485 方案，板子已就绪（需占用 USART2） |
| **USB** | J9 接 PA11/PA12（经 10Ω）→ **与 CAN1 共用** | 就是 P21 要二选一的原因 |
| **FSMC / LCD** | 明确标注 `PD0/FSMC_D2`、`PD1/FSMC_D3` | ✅ 印证：**CAN1 不能用默认的 PD0/PD1** |
| **ESP 模块** | "串口4 WIFI 模块接口"，UART4（**PA0/PA1**），CH_PD 侧有 10K 上拉（R53/R55/R54） | 与固件（UART4 + PF14 控制 CH_PD）一致 |
| 按键 | 板上既有 **5 向按键**，也有 **KEY0..KEY3** 网络 | 固件用 PF9/PF8/PF7/PF6 = KEY0..KEY3 |
| 板载外设 | W25Q128(SPI Flash)、OV2640(摄像头)、WM8978/VS1053(音频)、以太网 PHY、AT24C02 | 本实验不用，注意别和 FSMC/SPI 抢引脚 |

## 三、结论 → 已回写到方案文档

1. **CAN1 引脚 PA11/PA12 —— 原理图证实，不用改。**
2. **上板前必须把 P21 短接到 CAN 档（3–5、4–6）** —— 已写入 `docs/验收演示脚本.md`。
3. **不要外接 120Ω**（板载已有；三板共 ~40Ω）—— 已写入验收脚本的接线检查。
4. **I2C 上拉板上已有**，SGP30/SHT30 直接并上去即可。
