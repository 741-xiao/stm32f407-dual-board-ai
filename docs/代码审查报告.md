## 一、本轮已修（`5c60f5d`、`9e9c4fb`）

| # | 问题 | 为什么危险 | 修法 |
|---|---|---|---|
| 1 | `Light_Init()` 里 ADC 校准是 **无界 `while`** | ADC 时钟/外设异常 → **死等**，任务出不来 | 加 20 万次计数超时，超时也不阻塞 |
| 2 | 状态页每 200ms **全屏 `LCD_Clear`** | 一次写 240×320=**76800 个点**（≈8ms 忙写），每秒 5 次纯浪费 | 去掉；换页时由 DisplayTask 清一次 |
| 3 | `KeyTask`/`DebugTask` 栈 **256 字（1KB）** | `UART_Printf` 在**调用者栈**上开 **192B** 格式化缓冲，新增按键日志后偏紧 | 都提到 320 字 |
| 4 | `App_I2CRecover()` 用了 **`MX_I2C1_Init()`** | 它失败会调 `Error_Handler()` = **关中断死循环** → 把"可恢复的传感器故障"变成**整机死机** | 改用 `HAL_I2C_Init()`（只返回状态码） |
| 5 | `Error_Handler()` = **静默 `while(1)`** | 任何外设初始化失败都**无声死机**，现场只能猜 | 改成**闪 LED0（PE3）**——初始化失败看得见（本段在 USER CODE 区，CubeMX 会保留） |

## 二、建议改（需你决定 / 需上板验证）

| # | 项 | 说明 | 建议 |
|---|---|---|---|
| 1 | **没开栈溢出检测** | `configCHECK_FOR_STACK_OVERFLOW` 未定义 → 栈溢出**不报警**，直接踩内存 | 在 **CubeMX → FREERTOS → Config parameters** 加 `configCHECK_FOR_STACK_OVERFLOW=2`（★ 别手改生成文件，会被覆盖） |
| 2 | **I2C 恢复只做了 DeInit+Init** | 若从机把 SDA **拉死**，DeInit/Init 释放不了总线 —— 需要手动打 **9 个 SCL 时钟** | 在 `App_I2CRecover()` 里加"9 时钟脉冲"（把 PB6 临时切成 GPIO 输出） |
| 3 | **UART 发送是阻塞轮询** | `HAL_UART_Transmit` 在 115200 下发一行 ~3.5ms（持 TX 互斥锁） | 1Hz 日志可接受；要更稳可上中断/DMA + 环形发送队列 |
| 4 | **CAN 两帧的原子性** | `DATA_A` 成功、`DATA_B` 失败时，下一拍会**重发 A**（重复一帧 A） | 1Hz 下影响可忽略；要严格可加"半包暂存再补 B" |
| 5 | **`__disable_irq()` 在 Error_Handler 里保留** | 失败后 FreeRTOS 不再运行（符合"初始化失败即停"语义） | 保留；闪 LED 已够定位 |
| 6 | **`configASSERT` 也是死循环** | CubeMX 默认 `taskDISABLE_INTERRUPTS(); for(;;);` | 保留（开发期暴露问题），或改成闪 LED 同款 |

## 三、实验五的同一批问题（未改，仅记录）

实验五有**完全相同**的几处，本次**没有动**（避免改动已验证工程）：

- `Light_Init()` ADC 校准无界自旋
- 传感器初始化在 `App_Init`（调度器启动前）→ I2C 卡住整机起不来
- I2C 超时 100ms
- 驱动层 `delay_ms` 忙等（SGP30 12ms 在 SensorTask 里自旋）

**要改的话，实验六这套可以直接照搬**（`App_I2CRecover` / 两段式 SGP30 / 状态页 / Error_Handler 闪灯）。

## 四、审查后判定"可接受、不用改"

| 项 | 理由 |
|---|---|
| `lcd.c` 的 `delay_ms(120/10/12)` | 都在 `LCD_Init()`，跑在 **App_Init（调度器启动前）**，那时没有别的任务可饿 |
| `sht30.c` Init 2ms / `sgp30.c` Init 10ms | **一次性**、协议要求；已在任务开头各发生一次 |
| `LOCK()` 用 `portMAX_DELAY` | 持锁区都很短、无嵌套、无阻塞调用，不构成死锁条件 |
| `LedFx_*` / ESP AT 状态机 | 扫过：**无 delay、无自旋**，本来就是非阻塞设计 |
| `g_can_tx_cnt` 等统计量不加锁读 | 32 位对齐读在 Cortex-M4 上是原子的 |
| 采样/CAN 1Hz、TX gap 120ms | 实验五实测定档的吞吐口径 |

---

## 五、结论

- **"卡死"两类真源头已消除**：① 无界自旋（ADC 校准）② 初始化失败静默死循环（Error_Handler）。
- **阻塞**：任务内已无自旋；剩余阻塞均为一次性或极短。
- **可见性**：失败不再只靠串口 —— LED 闪（初始化失败）+ 状态页（运行时健康度）。
- 三 Target 编译 **0 Error 0 Warning**。
